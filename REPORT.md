## 3. Индивидуальные исходные данные для N = 69

Согласно методическим указаниям для Варианта Б параметры ряда рассчитываются по номеру по журналу $N = 69$:

1. **Базовый уровень суточного дебита ($B$):**
   $$B = 55.0 + 2.5 \cdot N = 55.0 + 2.5 \cdot 69 = 55.0 + 172.5 = 227.50\text{ м}^3/\text{сут}$$

2. **Шаг суточных колебаний ($S$):**
   $$S = (N \pmod 4) + 1.5 = (69 \pmod 4) + 1.5 = 1.0 + 1.5 = 2.50\text{ м}^3/\text{сут}$$

3. **Нормативные коэффициенты Варианта Б ($\text{OFFSETS}_{12D}$):**
   $$\text{OFFSETS}_{12D} = [0.0,\; 1.0,\; -1.0,\; 2.0,\; 0.0,\; -2.0,\; 1.0,\; 8.0,\; -1.0,\; 2.0,\; 1.0,\; 3.0]$$
   *(На 8-е сутки присутствует технологический выброс с коэффициентом $+8.0 \cdot S$)*.

### Пошаговый расчёт точек суточного дебита $Q_i = B + S \cdot \text{offset}_i$:
- **День 1:** $227.50 + 2.50 \cdot 0.0 = 227.50\text{ м}^3/\text{сут}$
- **День 2:** $227.50 + 2.50 \cdot 1.0 = 230.00\text{ м}^3/\text{сут}$
- **День 3:** $227.50 + 2.50 \cdot (-1.0) = 225.00\text{ м}^3/\text{сут}$
- **День 4:** $227.50 + 2.50 \cdot 2.0 = 232.50\text{ м}^3/\text{сут}$
- **День 5:** $227.50 + 2.50 \cdot 0.0 = 227.50\text{ м}^3/\text{сут}$
- **День 6:** $227.50 + 2.50 \cdot (-2.0) = 222.50\text{ м}^3/\text{сут}$
- **День 7:** $227.50 + 2.50 \cdot 1.0 = 230.00\text{ м}^3/\text{сут}$
- **День 8:** $227.50 + 2.50 \cdot 8.0 = 247.50\text{ м}^3/\text{сут}$ (технологический всплеск)

## 4. Ручной контрольный пересчёт показателей

Для верификации корректности машинных алгоритмов проведём полный ручной пересчёт статистик.

### 4.1. Упорядоченный вариационный ряд
Ранжируем массив из $n = 12$ значений по возрастанию:
$$\text{ordered} = [222.50,\; 225.00,\; 225.00,\; 227.50,\; 227.50,\; 230.00,\; 230.00,\; 230.00,\; 232.50,\; 232.50,\; 235.00,\; 247.50]$$

Индексация элементов в упорядоченном ряду ($0 \dots 11$):
- $\text{ordered}[0] = 222.50$
- $\text{ordered}[1] = 225.00$
- $\text{ordered}[2] = 225.00$
- $\text{ordered}[3] = 227.50$
- $\text{ordered}[4] = 227.50$
- $\text{ordered}[5] = 230.00$
- $\text{ordered}[6] = 230.00$
- $\text{ordered}[7] = 230.00$
- $\text{ordered}[8] = 232.50$
- $\text{ordered}[9] = 232.50$
- $\text{ordered}[10] = 235.00$
- $\text{ordered}[11] = 247.50$

### 4.2. Суммарная добыча и среднее арифметическое
Сумма всех замеров:
$$Q_{sum} = 227.5 + 230.0 + 225.0 + 232.5 + 227.5 + 222.5 + 230.0 + 247.5 + 225.0 + 232.5 + 230.0 + 235.0 = 2765.00\text{ м}^3$$

Среднее арифметическое:
$$\bar{Q} = \frac{Q_{sum}}{n} = \frac{2765.00}{12} = 230.416666\dots \approx 230.42\text{ м}^3/\text{сут}$$

### 4.3. Медиана
Количество элементов $n = 12$ является чётным. Центральными являются два элемента с индексами $n/2 - 1 = 5$ и $n/2 = 6$:
$$\text{mid} = 12 // 2 = 6$$
$$Me = \frac{\text{ordered}[5] + \text{ordered}[6]}{2} = \frac{230.00 + 230.00}{2} = 230.00\text{ м}^3/\text{сут}$$

Разница между средним и медианой:
$$\bar{Q} - Me = 230.42 - 230.00 = +0.42\text{ м}^3/\text{сут}$$
*(Положительная разница указывает на правостороннюю асимметрию ряда из-за пика на 8-е сутки)*.

### 4.4. Экстремумы и размах вариации
- Минимальный дебит: $Q_{min} = 222.50\text{ м}^3/\text{сут}$ (сутки 6)
- Максимальный дебит: $Q_{max} = 247.50\text{ м}^3/\text{сут}$ (сутки 8)
- Размах вариации:
  $$R = Q_{max} - Q_{min} = 247.50 - 222.50 = 25.00\text{ м}^3/\text{сут}$$

### 4.5. Первые точки скользящей средней (SMA)
1. **$SMA(3)_1$ за дни 1..3:**
   $$SMA(3)_1 = \frac{Q_1 + Q_2 + Q_3}{3} = \frac{227.50 + 230.00 + 225.00}{3} = \frac{682.50}{3} = 227.50\text{ м}^3/\text{сут}$$
2. **$SMA(3)_2$ за дни 2..4:**
   $$SMA(3)_2 = \frac{Q_2 + Q_3 + Q_4}{3} = \frac{230.00 + 225.00 + 232.50}{3} = \frac{687.50}{3} = 229.1666\dots \approx 229.17\text{ м}^3/\text{сут}$$
3. **$SMA(5)_1$ за дни 1..5:**
   $$SMA(5)_1 = \frac{Q_1 + Q_2 + Q_3 + Q_4 + Q_5}{5} = \frac{227.50 + 230.00 + 225.00 + 232.50 + 227.50}{5} = \frac{1142.50}{5} = 228.50\text{ м}^3/\text{сут}$$

Все ручные результаты полностью совпали с программными расчётами.

### 5.3. Файл `src/well_series/analytics.py`
```python
"""Математическое ядро: статистики ряда, скользящая средняя и оценка тренда.

Все алгоритмы реализованы на чистом Python без использования сторонних
библиотек (numpy, pandas, statistics) и встроенных функций min(), max(), sum().
"""

from well_series import config


def build_series_12d(student_n: int) -> list[float]:
    """Генерирует 12-суточный ряд дебитов для студента с номером N."""
    base = 55.0 + 2.5 * student_n
    step = float(student_n % 4) + 1.5
    return [round(base + k * step, 2) for k in config.OFFSETS_12D]


def calc_mean(series: list[float]) -> float:
    """Вычисляет среднее арифметическое числового ряда через аккумулятор."""
    if not series:
        raise ValueError("Пустой числовой ряд")
    total = 0.0
    for x in series:
        total += x
    return total / len(series)


def calc_median(series: list[float]) -> float:
    """Вычисляет медиану числового ряда без мутации исходного списка."""
    n = len(series)
    if n == 0:
        raise ValueError("Пустой числовой ряд")
    ordered = sorted(series)
    mid = n // 2
    if n % 2 == 1:
        return ordered[mid]
    return (ordered[mid - 1] + ordered[mid]) / 2.0


def calc_extremes_and_range(series: list[float]) -> tuple[float, float, float]:
    """Находит минимум, максимум и размах вариации за один проход цикла."""
    if not series:
        raise ValueError("Пустой числовой ряд")
    lo = hi = series[0]
    for x in series[1:]:
        if x < lo:
            lo = x
        if x > hi:
            hi = x
    return lo, hi, round(hi - lo, 2)


def calc_sma_aligned(series: list[float], window: int) -> list[float | None]:
    """Вычисляет выровненный по исходной длине список скользящей средней SMA.

    Первые (window - 1) элементов заполняются None (фаза накопления окна),
    а последующие содержат среднее арифметическое среза series[i : i + window].
    """
    if window <= 0 or window > len(series):
        raise ValueError(f"Окно {window} недопустимо для ряда длины {len(series)}")
    result: list[float | None] = [None] * (window - 1)
    for i in range(len(series) - window + 1):
        chunk = series[i : i + window]
        result.append(round(calc_mean(chunk), 2))
    return result


def calc_moving_average(series: list[float], window: int) -> list[float]:
    """Вычисляет чистый список скользящей средней SMA без None.

    Длина результирующего списка строго равна (len(series) - window + 1).
    """
    if window <= 0 or window > len(series):
        raise ValueError(f"Окно {window} недопустимо для ряда длины {len(series)}")
    result: list[float] = []
    for i in range(len(series) - window + 1):
        chunk = series[i : i + window]
        result.append(round(calc_mean(chunk), 2))
    return result


def detect_trend(sma_aligned: list[float | None]) -> str:
    """Определяет общий тренд дебита по первой и последней доступной точке SMA."""
    valid = [x for x in sma_aligned if x is not None]
    if len(valid) < 2:
        return "недостаточно данных"
    diff = valid[-1] - valid[0]
    if diff > 1.0:
        return f"восходящий (+{diff:.2f} м³/сут)"
    elif diff < -1.0:
        return f"нисходящий ({diff:.2f} м³/сут)"
    return f"стабильный ({diff:+.2f} м³/сут)"


def calc_total_and_peak_share(series: list[float]) -> tuple[float, float, float]:
    """Вычисляет суммарную добычу Q_sum, максимальный замер и долю пиковых суток."""
    if not series:
        raise ValueError("Пустой числовой ряд")
    q_sum = 0.0
    for x in series:
        q_sum += x
    _, max_v, _ = calc_extremes_and_range(series)
    peak_share = (max_v / q_sum) * 100.0 if q_sum > 0 else 0.0
    return round(q_sum, 2), round(max_v, 2), round(peak_share, 2)


def filter_days_above_mean(series: list[float]) -> tuple[float, list[int]]:
    """Фильтрует номера суток, дебит которых строго превышает средний уровень."""
    mean_val = round(calc_mean(series), 2)
    days = [day for day, q in enumerate(series, start=1) if q > mean_val]
    return mean_val, days
```

### 5.4. Файл `src/well_series/main.py`
```python
"""Консольный интерфейс аналитической станции временных рядов (Вариант Б)."""

import sys

from well_series import analytics, config


def render_bar(val: float, min_v: float, max_v: float) -> str:
    """Строит текстовую полоску '#' пропорционально значению в диапазоне [min_v; max_v]."""
    span = max_v - min_v
    if span <= 0:
        return "#" * 10
    ratio = (val - min_v) / span
    count = 1 + int(round(ratio * (config.BAR_MAX_WIDTH - 1)))
    return "#" * count


def main() -> None:
    """Точка входа в консольное приложение."""
    print("АНАЛИТИЧЕСКАЯ СТАНЦИЯ ОБРАБОТКИ ВРЕМЕННЫХ РЯДОВ (ВАРИАНТ Б)")
    print("=" * 74)

    if "--auto" in sys.argv:
        student_n = config.DEFAULT_STUDENT_N
        print(f"Автоматический запуск для номера по журналу N = {student_n}")
    else:
        try:
            raw = input(
                f"Введите ваш номер по журналу N [Enter = {config.DEFAULT_STUDENT_N}]: "
            ).strip()
            if not raw:
                student_n = config.DEFAULT_STUDENT_N
            elif raw.isdigit() and int(raw) > 0:
                student_n = int(raw)
            else:
                print(f"Некорректный ввод, используется значение по умолчанию N = {config.DEFAULT_STUDENT_N}")
                student_n = config.DEFAULT_STUDENT_N
        except (EOFError, KeyboardInterrupt):
            student_n = config.DEFAULT_STUDENT_N
            print(f"\nИспользуется значение по умолчанию N = {student_n}")

    rates = analytics.build_series_12d(student_n)
    mean_v = analytics.calc_mean(rates)
    med_v = analytics.calc_median(rates)
    min_v, max_v, rng_v = analytics.calc_extremes_and_range(rates)
    sma3 = analytics.calc_sma_aligned(rates, config.SHORT_WINDOW)
    sma5 = analytics.calc_sma_aligned(rates, config.LONG_WINDOW)
    trend_str = analytics.detect_trend(sma3)

    print(f"\nХронологический ряд (12 сут.): {rates}")
    print("-" * 74)
    print(
        f"Среднее: {mean_v:.2f} | Медиана: {med_v:.2f} | "
        f"Разница (Среднее - Медиана): {mean_v - med_v:+.2f}"
    )
    print(
        f"Минимум: {min_v:.2f} | Максимум: {max_v:.2f} | "
        f"Размах вариации R: {rng_v:.2f} м³/сут"
    )
    print(f"Оценка тренда по SMA({config.SHORT_WINDOW}): {trend_str}")

    print("\nСВОДНАЯ ТАБЛИЦА СГЛАЖИВАНИЯ И ВИЗУАЛИЗАЦИИ РЯДА")
    print("-" * 74)
    print(
        f"{'День':<6}{'Q факт':>10}{'SMA(3)':>10}{'SMA(5)':>10}"
        f"{'Откл. от SMA(3)':>16} {'Профиль дебита'}"
    )
    print("-" * 74)
    for idx, q in enumerate(rates):
        day = idx + 1
        s3 = sma3[idx]
        s5 = sma5[idx]
        s3_str = f"{s3:10.2f}" if s3 is not None else f"{'—':>10}"
        s5_str = f"{s5:10.2f}" if s5 is not None else f"{'—':>10}"
        dev_str = f"{q - s3:+16.2f}" if s3 is not None else f"{'—':>16}"
        bar = render_bar(q, min_v, max_v)
        print(f"{day:<6}{q:>10.2f}{s3_str}{s5_str}{dev_str} {bar}")

    q_sum, max_val, peak_share = analytics.calc_total_and_peak_share(rates)
    mean_val, above_days = analytics.filter_days_above_mean(rates)

    print("-" * 74)
    print("РЕЗУЛЬТАТЫ ДОПОЛНИТЕЛЬНОГО АНАЛИЗА (УПРАЖНЕНИЯ 5 И 6)")
    print("-" * 74)
    print(f"Суммарная добыча Q_sum: {q_sum:.2f} м³")
    print(f"Максимальный суточный дебит max_v: {max_val:.2f} м³/сут")
    print(f"Доля пиковых суток в общей добыче: {peak_share:.2f}%")
    print(
        f"Сутки выше среднего ({mean_val:.2f} м³/сут): "
        f"{len(above_days)} из {len(rates)} дн. -> {above_days}"
    )
    print("=" * 74)


if __name__ == "__main__":
    main()
```

## 8. Ответы на контрольные вопросы для защиты (Раздел 11)

### Вопрос 1. Чем отличается расчёт медианы для числового ряда с нечётным количеством элементов (например, 11 суток) и с чётным количеством элементов (10 или 12 суток)? Покажите строки вашего кода, которые за это отвечают.

**Ответ:**
Для нечётного количества элементов вариационного ряда существует строго один центральный элемент, индекс которого находится операцией целочисленного деления `mid = n // 2`. Например, для ряда длины $n = 13$ (как в Упражнении № 1) `mid = 13 // 2 = 6`, и медианой является `ordered[6] = 230.00` м³/сут.
Для чётного количества элементов центральными являются два соседних элемента с индексами `mid - 1` и `mid`. В этом случае медиана определяется как их полусумма (среднее арифметическое). В нашем базовом ряду ($n = 12$) `mid = 12 // 2 = 6`, центральные элементы `ordered[5] = 230.00` и `ordered[6] = 230.00`, а медиана равна `(230.00 + 230.00) / 2.0 = 230.00` м³/сут.

В модуле `src/well_series/analytics.py` за эту логику отвечают строки 48–57:
```python
    ordered = sorted(series)
    mid = n // 2
    if n % 2 == 1:
        return ordered[mid]
    return (ordered[mid - 1] + ordered[mid]) / 2.0
```

### Вопрос 2. Почему внутри функции `calc_median` необходимо использовать функцию `sorted(series)`, а не списочный метод `series.sort()`? Как именно изменится результат работы функции `calc_moving_average`, если массив отсортируется «на месте»?

**Ответ:**
В Python списки являются изменяемыми объектами (`mutable`), которые передаются в аргументы функций по ссылке. Списочный метод `series.sort()` выполняет сортировку «на месте» (`in-place`), мутируя сам исходный массив, переданный вызывающей стороной, и возвращает `None`. В отличие от него, встроенная функция `sorted(series)` создаёт и возвращает **новый** упорядоченный список, оставляя исходный массив нетронутым.
Если применить `series.sort()`, то хронологическая ось времени будет безвозвратно разрушена: замеры выстроятся по возрастанию дебита ($[222.50, 225.00, \dots, 247.50]$). В результате последующий вызов `calc_moving_average` будет усреднять не технологические замеры по соседним дням, а соседние квантили распределения, что превратит скользящую среднюю в искусственный монотонно растущий ряд $[224.17, 225.83, 226.67, \dots]$, как наглядно доказано в Упражнении № 4.

### Вопрос 3. Как работает срез списка `series[i : i + window]` в алгоритме скользящей средней? Почему при длине ряда $n = 10$ и ширине окна $k = 3$ получается ровно 8 значений скользящей средней, а не 10?

**Ответ:**
Срез в Python `series[start : stop]` извлекает подпоследовательность элементов начиная с индекса `start` (включительно) и заканчивая индексом `stop` (не включая его!). Число элементов в срезе равно `stop - start`. При `series[i : i + window]` длина среза строго равна `(i + window) - i = window`.
Для расчёта первого значения скользящей средней окно должно накопить первые $k$ замеров (дни $1 \dots k$). Таким образом, первые $k - 1$ суток не имеют достаточной предыстории для формирования полного окна сглаживания. Из общего числа $n$ суток вычитается фаза накопления:
$$L = n - (k - 1) = n - k + 1$$
При $n = 10$ и $k = 3$ получаем $10 - 3 + 1 = 8$ значений. В нашем проекте для Варианта Б при $n = 12$ и $k = 3$ получается $12 - 3 + 1 = 10$ значений (а при $k = 5$ — ровно $12 - 5 + 1 = 8$ значений).

### Вопрос 4. Какой статистический показатель — среднее арифметическое или медиана — сильнее реагирует на единичный аварийный выброс датчика и почему? Приведите численный пример из вашего Упражнения № 2.

**Ответ:**
На единичный аварийный выброс неизмеримо сильнее реагирует **среднее арифметическое**. Причина в том, что среднее вычисляется суммированием всех значений $\frac{1}{n}\sum Q_i$, поэтому аномальное значение любой величины непосредственно увеличивает общую сумму и смещает среднее на $\frac{\Delta Q}{n}$. 
Медиана же является ранговой (порядковой) статистикой: она зависит только от того, какие значения находятся в геометрическом центре вариационного ряда. Пока выброс остаётся по одну из сторон от центра (в хвосте распределения), позиция и значения центральных элементов не меняются.
**Численный пример из Упр. 2 (N = 69):**
При замене замера 12-х суток с $235.00$ на $500.00$ м³/сут:
- Среднее арифметическое подскочило с $230.42$ до $252.50$ м³/сут (рост на $+22.08$ м³/сут, в нормативном приближении ТЗ — рост на $+18.12$ м³/сут до $248.54$ м³/сут).
- Размах вариации подскочил с $25.00$ до $277.50$ м³/сут (рост в 11 раз).
- **Медиана осталась абсолютно неизменной:** ровно $230.00$ м³/сут ($0.00$ м³/сут смещения).

### Вопрос 5. Как меняется поведение кривой скользящей средней при увеличении ширины окна сглаживания $k$ (например, с $k = 3$ до $k = 5$)? В чём состоит компромисс между степенью сглаживания шума и запаздыванием оценки тренда?

**Ответ:**
При увеличении ширины окна $k$ с 3 до 5 происходят два взаимосвязанных физических процесса:
1. **Подавление волатильности (сглаживание шума):** размах колебаний ряда скользящей средней уменьшается (в нашем эксперименте с $8.33$ м³/сут у $SMA(3)$ до $6.50$ м³/сут у $SMA(5)$). Резкий пик 8-х суток ($247.50$ м³/сут) при $k=3$ сглаживается до $235.00$ м³/сут, а при $k=5$ — ещё сильнее, до $234.00$ м³/сут. График становится гладким.
2. **Фазовое запаздывание (лаг тренда) и потеря данных:** скользящая средняя начинает сильнее запаздывать во времени относительно резких изменений фактического дебита скважины. Кроме того, увеличивается начальная «мёртвая зона» накопления: при $k=3$ теряются первые 2 суток, а при $k=5$ — уже 4 суток ($k - 1$).
**Инженерный компромисс:** Малое окно ($k = 3$) быстрее реагирует на изменение режима скважины (минимальный лаг), но пропускает случайный высокочастотный шум. Большое окно ($k = 5$) надёжно отфильтровывает помехи и технологические сбои, но с задержкой сообщает аналитику о начале реального падения или роста добычи.
